## 2. How to continue on the new machine

1. Clone/pull `main`. A JDK 17+ on PATH (the mod's `compile.ps1` and the simulator's `build.ps1`
   both need `javac`); Perl (Git's `usr/bin/perl.exe` is enough) for `tools/gen-symbols.pl`, which
   `compile.ps1` calls to regenerate `docs/symbols.md`.
2. `powershell -NoProfile -ExecutionPolicy Bypass -File tools/warsim/build.ps1`, then the base:
   `tools/warsim/warsim.ps1 batch -seeds 30 -start tools/warsim/start/pd9a-newgame -killWeight 1`
   and the same with `-start tools/warsim/start/pd9a-month114 -months 48`. Expect (medians) new game
   humanScore about 28, threatScore about 890, hives killed 8; mid-war humanScore about 33, threatScore
   about 340 (the round-18 humans-only base, `war-sim-humans.md` 13). `-set k=v;k2=v2` lays a cell on
   top; `compare` takes two sets on the same seeds and says "clear" by the p10-p90 rule.
3. A round is an agent job: brief it with the objective above, the facts.md lines and doc sections
   it needs, 60 seeds for anything that looks like a winner, a time box, and "commit code and docs
   as each part lands". Build a winner into the mod yourself: settings.json + LunaSettings.csv +
   a `LunaConfigBridge` migration bump for a changed default (a new key needs none), rebuild out of
   process (`compile.ps1`, game closed), then a 5-minute mid-war game check (Fleets Ignore You ON for
   the run, OFF after; `docs/testing-harness.md`). **Before building a knob winner, grep every reader
   of the knob in `src/threatinc`** - round 18's lesson - and have the simulator confirm the new
   defaults reproduce the winning cell.
4. The game-side checks need a Starsector install with the mod folder as the git checkout, LunaLib,
   and a mid-war save (this machine's `ng9`; on a new machine make one with
   `tools/test-harness/fastforward`, `docs/testing-harness.md`, or run new-game checks only).
